# A 담당 배포 절차

## 현재 상태

AWS 리전: `us-east-1` (버지니아 북부). 웹 콘솔 로그인만 확인되었으며 로컬 SDK 인증은 확인되지 않았습니다.
현재 코드만으로 AWS 리소스를 만들지는 않았습니다.

## 콘솔에서 GitHub 연결로 배포

1. 팀원들과 공유할 작업 브랜치를 GitHub에 업로드합니다. 기존 다른 앱을 수정하지 않습니다.
2. Amplify 콘솔에서 새 앱 생성 → GitHub → 이 팀 저장소와 합의한 브랜치를 선택합니다.
3. GitHub 연결 승인 시 이 저장소에 필요한 접근을 부여합니다. 필요하면 저장소 관리자에게 요청합니다.
4. 코드에 있는 `amplify.yml`을 사용합니다. 앱 루트는 저장소 루트입니다.
5. Gen 2 백엔드를 배포할 Amplify 서비스 역할을 선택/생성합니다. 대회 IAM 사용자에게 역할 생성·전달 권한이 없으면 주최 측에 요청합니다.
6. 배포하면 Cognito, AppSync, Lambda, DynamoDB 리소스가 생성됩니다. 사용 비용이 발생할 수 있습니다.
7. 성공 후 앱의 백엔드 출력 설정을 내려받아 로컬 루트 `amplify_outputs.json`에 둡니다. 브라우저용 연결 설정이며 비밀 키가 아닙니다.
8. 통합 담당자가 `configureBackend(outputs)`를 앱 진입점에 연결합니다. 생성 파일은 Git에 커밋하지 않습니다.

빌드는 Node.js 24에서 `npm ci` → 백엔드 타입 검사 → 테스트 → `ampx pipeline-deploy` → 프런트 빌드 순서입니다.
프런트 산출물은 `dist`입니다. 사용자 정의 라우팅을 추가할 때 SPA 재작성 규칙도 설정해야 합니다.

## 로컬 sandbox 경로 (나중에 필요할 때)

웹 콘솔 로그인만으로는 실행되지 않습니다. 대회에서 승인한 개발용 인증을 먼저 설정합니다.
설정 후 `npm run sandbox:once -- --profile 프로필이름`을 사용할 수 있습니다.
이 명령은 로컬 가짜 서버가 아니라 실제 AWS 리소스를 생성합니다. 계정과 리전이 올바른지 확인한 후 실행합니다.

## 배포 후 필수 확인

- 계정 A/B/C 세 개를 이메일 인증 후 준비 (C는 방에 미참여)
- A 방 생성 → 초대 → B 참여 → 두 계정에서 같은 상태 조회
- A 타임블록 생성 → B 핀 생성 → A 메모 수정 → 양쪽 실시간 반영
- 두 사용자 동시 수정 시 한 요청은 CONFLICT로 거절
- C의 방 조회/쓰기/구독 거절 및 다른 방 타임블록에 핀 생성 거절
- 네트워크 재연결과 새로고침 이후 데이터 복구
- AI 연동은 C 담당 함수와 연결한 뒤 별도 검증

## 비용과 종료 후 정리

DynamoDB는 요청량 기반 과금이며 데이터를 실수로 잃지 않도록 RETAIN으로 설정했습니다.
앱/스택을 삭제해도 테이블이 남을 수 있으므로 대회 종료 후 팀 데이터 보관 여부를 결정하고 리소스를 점검합니다.
초대 레코드는 TTL을 사용하지만 만료 여부는 삭제 시점과 별개로 서버가 직접 검사합니다.
