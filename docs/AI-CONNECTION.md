# 실제 AI·장소 검색 로컬 연결

대회 안내의 OpenAI 호환 API를 서버에서 호출합니다. 선택 모델은 `bedrock-gpt-5.6-sol`입니다.
이 이름은 대회 게이트웨이 모델 ID이며 AWS Bedrock SDK를 직접 호출하는 방식은 아닙니다.

## 실행

`.env.example`을 참고해 `.env.local`을 작성합니다. 기존 파일이 있으면 덮어쓰지 마세요.

```dotenv
API_KEY=대회에서_발급한_키
AI_BASE_URL=https://52.79.201.46/v1
AI_MODEL=bedrock-gpt-5.6-sol
KAKAO_REST_API_KEY=카카오_REST_API_키
VITE_LOCAL_BACKEND=true
```

`npm run dev -- --port 5175` 실행 후 `http://127.0.0.1:5175/`로 접속합니다.
API 키에 `VITE_` 접두사를 붙이지 않습니다. 브라우저용 카카오 JavaScript 키와 REST 키는 다릅니다.
실제 AI와 카카오 호출에는 해당 계정의 API 사용량이 발생합니다.

## 화면에서 확인

1. `@AI 부산 해운대 여행에서 주의할 점을 두 문장으로 알려줘.` → 실제 AI 응답이 채팅에 나타납니다.
2. `@AI 1일차 해운대 산책 타임블록에 해운대 해변 근처 카페 한 곳을 검색해서 핀 찍어줘.` → 카카오 결과의 이름·장소 ID·좌표로 핀을 저장합니다.
3. 페이지를 새로고침해 대화와 저장된 핀이 남는지 확인합니다.
4. 타임블록 지정 없이 `@AI 카페 핀 찍어줘.`라고 하면 대상 확인 질문이 나오며 핀은 추가하지 않습니다.

검색 결과가 없으면 핀을 만들지 않고 채팅에 알립니다. 여러 후보 가운데 현재는 검색 순서상 첫 결과를 저장합니다.
자연어 타임블록 식별은 `1일차`와 저장된 타임블록 이름의 일치를 지원합니다. 이름이 모호하면 전체 요청에 일차와 이름을 다시 명시하세요.

## 팀원 연결 기준

- 일반 데이터: 기존 `roomApi`와 `watchRoom`을 계속 사용합니다. 로컬 모드에서만 개발 서버로 전환됩니다.
- AI 실행: `runAiRequest`가 `/api/ai/run`을 호출합니다. 응답에 `persisted: true`가 있으면 이미 서버에 저장했으므로 화면에서 AI 메시지나 핀을 다시 저장하지 않습니다.
- 선택한 작업 타임블록 ID는 `ChatPanel`의 `selectedTimeBlockId`로 전달합니다. 지도 표시 필터와 별도로 관리합니다. 채팅에서 명시한 타임블록이 우선입니다.
- 장소 검색: `searchPlaces`가 `/api/places/search`를 호출합니다. 서버가 카카오 REST 키를 사용합니다.
- 필드·함수 변경은 A/B/C가 협의한 뒤 공통 규격에 반영합니다.

## 저장과 배포의 구분

이 모드는 동일한 백엔드 검증 함수를 사용하지만 저장소는 `.local-data/rooms.json`입니다.
`local-test-user` 한 명으로 동작하며 Cognito 로그인이나 AWS 배포를 검증한 것은 아닙니다.
같은 컴퓨터의 여러 탭은 로컬 이벤트로 변경을 받습니다. 다른 팀원의 컴퓨터나 인터넷 공개 사이트로 공유되지는 않습니다.
`.env.local`과 `.local-data/`는 Git에서 제외됩니다.

개발 서버는 루프백 주소에서만 이용합니다. 이 고정 사용자 테스트 서버를 외부에 공개하지 마세요.
`npm run build`와 `npm run preview`에는 이 개발용 API가 포함되지 않습니다.
공개 배포에는 인증된 AWS 서버 함수로 AI 실행을 옮기고 키 설정·접근 권한·실시간 이벤트를 연결해야 합니다.
